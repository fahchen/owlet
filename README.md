## 视觉与交互原型

直接在浏览器打开 [design/index.html](design/index.html)。HTML、CSS、JavaScript 和图标均内嵌于同一文件，无安装步骤或网络依赖。

即时处理使用 macOS Spotlight 风格的浮动工具栏，文本处理、快捷键与设置使用完整管理窗口。

原型使用中英日内置样例：翻译、润色、快捷键录制、设置、生词本、历史、学习表达、逐句对照、Prompt 编辑、响应式双栏、目标语言映射与菜单栏入口都是已实现的功能，每张画面都对应应用里已落地的东西；`success`（写回完成确认）保留旧画面，原生应用写回成功后直接关闭浮窗。展开面板的「替换」把模拟原选区改成译文；`direct-loading` 用状态文字表示“翻译并替换…”。右上角可切换请求失败与未能写回场景。

原型所有画面的侧边栏都是目标形态（含生词本与历史记录），实现进度由徽标与文档说明。原型的窗口骨架与控件都已经换成 macOS 26 原生组件的外观：可收起的系统侧边栏，跨整窗的工具栏（目标语言弹出式按钮、翻译／润色分段控件），提交与复制仍在底部操作栏，内容区的分组表单与内联状态提示。文本处理页在内容区不足 720pt 时原文与译文上下堆叠，足够宽时左右并排（`ProcessingLayout.choose(width:)`，阈值 720pt）。每个组件到原生 SwiftUI / AppKit 组件的对照见 [Liquid Glass 组件对照](docs/liquid-glass-components.md)；其中三处例外只有两处已实现，另一处仍是待做设计。

界面文案的三条规则（动作区只放动作，不放解释性文字；不把快捷键画进界面；按钮只用动词，宾语交给上下文）仍是提案：当前文本处理页在“原文”右侧画 `⌘ V 粘贴`，浮动面板动作行左端显示快捷键提示，按钮读作 `翻译文本` / `润色文本` / `保存设置`。规则原文与差异见 [视觉与交互规则](spec/DESIGN.md)。

快捷键无默认组合；Esc 关闭；原型只在内存中保存当前状态，不写入浏览器存储，API Key 不保存，也不调用真实模型。任意文本翻译、系统快捷键和 macOS 跨应用替换已在原生应用实现。

### 原型检查

在浏览器打开文件后依次操作：

1. 在文本处理页输入文本或切换到内置样例，翻译后确认译文显示、“复制”可用；收起侧边栏确认页面不变。
2. 在展开面板点「替换」，确认模拟原选区被译文替换；原生应用写回成功后直接关闭浮窗。
3. 选择“未能写回”并再次执行，确认面板留在原地、说明未能写回，译文可复制；选区不可编辑时提示“原选区不可编辑”。
4. 选择“请求失败”并重新翻译，确认错误提示；处理期间点击停止，确认不写回。
5. 在快捷键页录制翻译与润色组合，Esc 取消、Delete 清除，确认初始无默认组合。
6. 在设置页保存模型服务并确认“已保存”；切到模型列表失败状态，确认就地提示与重试。

BDD 场景尚未绑定自动化步骤；原生应用已经实现原型中已实现的部分（文本处理、快捷键、设置、浮动面板与菜单栏）；提案画面与尚未实现的功能见 [未实现功能清单](docs/unimplemented-features.md)。

## 状态设计预览

页面上方的“状态预览”可直接切换 64 种状态，左右箭头逐个浏览。状态总览按窗口与面板分为十组竖向堆叠（应用窗口 · 文本处理、应用窗口 · 生词本、应用窗口 · 历史记录、应用窗口 · 快捷键、应用窗口 · 设置、浮动面板 · 紧凑条、浮动面板 · 直接替换 · 紧凑提示、浮动面板 · 学习表达区块、浮动面板 · 展开、菜单栏）；同一面板内的状态横向排列。状态预览只在内存中切换，不写入浏览器存储，原型也不真正保存收藏与历史。

- 应用窗口 · 文本处理：结果、空输入、已输入、处理中、润色结果、窄窗口、请求失败、服务未配置、侧栏收起、学习表达、自动目标、手动指定目标。
- 应用窗口 · 生词本：列表、详情、空状态、无搜索结果。
- 应用窗口 · 历史记录：列表、详情、空状态。
- 应用窗口 · 快捷键：未设置、录制中、组合冲突。
- 应用窗口 · 设置：模型服务、自定义服务商、已保存、学习开关、模型列表失败、模型列表读取中、Prompt 分组、目标语言（空表）、目标语言（已添加映射）。
- 浮动面板 · 紧凑条：翻译／润色／直接替换处理中、请求失败、格式错误、已取消、未授权、服务未配置、选区读取失败、未能写回。
- 浮动面板 · 直接替换 · 紧凑提示：读取失败、权限未授权、服务未配置、请求失败、格式错误、已取消；这六张与紧凑条里的对应状态是同一个组件，只是从“翻译并替换”捷径进入。
- 浮动面板 · 学习表达区块：展开、整理中、生成失败、无推荐、已入库。
- 浮动面板 · 展开：翻译结果、润色结果、长文本、逐句对照、结果区处理中、未能写回、结果区失败、结果区已取消、写回完成确认、空原文。
- 菜单栏：常驻入口、展开菜单。

浮层宽 560px，面板标题栏 42px，底部操作栏至少 45px。内容增长时内部滚动，复制／替换仍固定可见。浮层是功能层，材质集中在这里；内容层不叠玻璃。网页材质是视觉近似；原生 `NSGlassEffectView` 的折射与系统辅助功能适配在 macOS 实现阶段调校。

浏览器控制台运行 `checkDesignStates()` 可检查全部 64 个预览是否有操作栏、是否使用正确浮层及是否发生底部裁切。检查只切换状态，不改动任何数据。

翻译结果按原文与译文分区显示，长文本在面板内滚动；复制和替换只取译文。显示方式可切换为“逐句对照”，保存后持久化，完整窗口与浮层共用，切换显示不重新请求（`TranslationDisplayMode`）。

处理中使用约 430px 宽的单行紧凑条：选中文字摘要、加载指示、状态文字与右端停止按钮。不显示结果占位区、学习推荐或完整操作栏；按 `spec/product.md`，Esc 关闭并取消本次操作。整圈呼吸动画尚未实现（当前只用旋转指示），保留为待做设计，见 [未实现功能清单](docs/unimplemented-features.md)；展开动画已实现（`PanelView` 的 `.smooth(0.3)`，减少动态效果时关闭）。

浮层外观以 macOS Tahoe Spotlight 为参考：中性半透明材质、系统默认的玻璃外观（无自绘边框，投影跟随玻璃圆角）、单行处理条及下方结果展开。保留 Owlet 的翻译与润色动作，不复制搜索功能；网页材质是视觉近似，非系统原生渲染。参考：[Apple macOS Tahoe](https://www.apple.com/newsroom/2025/06/macos-tahoe-26-makes-the-mac-more-capable-productive-and-intelligent-than-ever/)。

设置页分组：模型服务、文本处理、学习、浮窗、Prompt。Prompt 分组可查看默认内容、编辑、保存与恢复默认，并展示 JSON 返回示例（`PromptSettingsView`）。默认 Prompt 与原生 JSON 契约见 [spec/llm/contract.md](spec/llm/contract.md)；原型不请求真实模型。

快捷键设置支持点击录制、Esc 取消、Delete／清除按钮清除，无默认组合；原型只把组合记在界面上，不做冲突检查也不持久化。组合冲突检查、系统级占用与全局注册由原生应用处理。

快捷键录制检查：初始三个动作均为“未设置”。在原型里录制翻译为 ⌃⌥T、润色为 ⌃⌥P 只会更新界面上的组合，不会注册；Esc 取消录制，点击清除或 Delete 清空。组合冲突检查与实际注册由原生应用负责。JSON 契约见 spec/llm/contract.md。

完整窗口左侧统一为“文本处理”，在同一页面选择翻译／润色，输入后执行并复制结果。在窗口工具栏或浮层头部切换翻译／润色时，同一段文字会立刻重新请求；切回上一个动作时直接用该段文字已算出的结果，不再发请求——这份缓存只跟着当前原文，原文一变即失效。侧边栏可以收起，收起后工具栏与功能不变。没有两个操作 tab，也不提供“翻译并替换”导航项。浮层头部的操作选择只有翻译与润色两项；页内结果不写回外部选区。

界面文案已移除介绍性标题、副标题和重复操作说明，但未完全采用文案规则：文本处理页仍显示 `⌘ V 粘贴`，按钮与面板动作行仍画出 ⌘↩ 等快捷键。图标保留可访问名称。

原型默认打开“状态总览”，按窗口与面板分组展示所有状态画面；右上角可调缩放，每个画面的 ↗ 可进入交互。`checkFlowBoard()` 检查 64 个状态是否全部出现、是否有重复，以及分组数是否与定义一致（10 组）。

展开面板的动作行左端是快捷键提示（`Esc 取消` / `快捷键未设置` / 已录制的全局快捷键 + ` 唤起`），右端是 `复制 ⌘⇧C` 与 prominent 的 `替换 ⌘↩`；重新处理位于浮窗右上角。学习表达区块内联在结果下方，勾选后入库，动作行不再放常驻收藏按钮（`LearningView`）。复制结果或写回成功都算一次完成的交互，浮窗随即关闭；浮窗也只在 Esc、显式关闭或点击浮窗外部时关闭，失去键盘焦点不关闭。

## 生产构建

Release、通用二进制（arm64 + x86_64）、验证后打包到 `dist/`（已在 `.gitignore` 里）：

```sh
mise run prod                       # 现在：ad-hoc 签名
mise run prod -- --arch arm64       # 只要本机架构，快一些
mise run prod -- --team Z98NKJSF69  # 有证书后：Apple Development 签名
```

脚本是 [scripts/prod-build.sh](scripts/prod-build.sh)，做的事：构建 → 校验（bundle id、最低系统版本、图标、签名可验证、不带 `get-task-allow`）→ 用 `ditto` 打包并打印 SHA-256。

两种签名的差别只在权限与提示：ad-hoc 的包拷到另一台 Mac 需要右键打开一次，而且**每次重编都要重新授权辅助功能**；`--team` 指定证书后签名带上 Team ID，授权一次就长期有效，但因为没有公证，首次打开仍会提示一次。用 `scp` 或 `rsync` 传，别用 AirDrop——前者不写 quarantine 标记。

`project.yml` 没有设 `MARKETING_VERSION`，所以产物名字用提交号（`Owlet-<commit>-universal.zip`）；想要版本号就在 `project.yml` 里加上这个设置，脚本会自动改用它。
