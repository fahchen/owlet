本地库设计

一个 ModelContainer，三张表。生词本两张（词条 + 语境，一对多），历史一张（独立，不与前两者关联）。下面是列定义、约束与示例数据。

SwiftData / CoreData 底层 Application Support 单库 无显式迁移版本 导出 version 1

表关系

容器在 VocabularyStore.makeContainer() 注册：ModelContainer(for: VocabularyEntry.self, VocabularyContext.self, HistoryRecord.self)。历史与生词本共用容器但模型集不相干，级联删除不会互相波及。

VocabularyEntry

收藏的表达本体。唯一键是 (language, expression) 复合键，expression 入库前已 trim——同一表达重复收藏不分叉成两行，只往 contexts 追加。

VocabularyContext

一条表达可以在多个句子里被收藏，每次收藏存一行。润色来源额外存前后对照。

VocabularyContext @Model Owlet/Vocabulary/VocabularyEntry.swift:28
列类型默认说明
source String "" 收藏时所在的整句。同时作为释义补充请求的上下文。
polishBefore可空 String? nil 润色前原文。仅当来源操作为 polish 时写入。
polishAfter可空 String? nil 润色后结果。与 before 成对写入，界面只在两者皆非 nil 时渲染对照。
createdAt Date Date() 不参与导出。
entry外键 VocabularyEntry? nil 反向引用。由 @Relationship 自动维护，不手工赋值。

去重不靠唯一键，靠 hasSameContent：source / polishBefore / polishAfter 三者各自 trim 后全等即视为同一条，不追加。已有语境永不被覆盖。

HistoryRecord

翻译 / 润色历史。与生词本无外键关系，但可作为收藏来源：从历史详情收藏时 expression = result、context = source，这样历史删除后词条仍保有原句。

写入规则

约束不全在 schema 里，一部分由 VocabularyStore 在写入路径上执行。

collect / update / delete store Owlet/Vocabulary/VocabularyStore.swift:20
1

expression 入库前 trim，空则拒绝

抛 VocabularyError.emptyExpression。唯一键比的是 trim 后的值，所以 " follow up " 与 "follow up" 是同一条。

2

命中既有词条则复用，只追加语境

先按 (language, expression) 查；命中且新语境 hasSameContent 不重复才 append。既有 meaning 不被覆盖。

3

meaning 后填，失败不回滚已存内容

收藏先落库，释义异步补。请求失败只落在 UI 状态，词条与语境已经存在，可在生词本里重试。

4

改名撞唯一键则拒绝

update 里同语言下已存在同名表达时报错，不做合并——身份始终是 (language, trimmed expression)。

5

删词条级联删语境

deleteRule: .cascade。反过来不成立：删语境不影响词条，词条可以 0 语境存在。

导出格式

只读 store，不改库。createdAt 与对象引用都不导出，version 让后续版本能认出文件形状。
