# 用户自定义的词条区块

状态：设计提案，未实现。形态已由用户确定：**不接本地词典来源**——词条的辞典内容由模型生成——在查词卡与生词本词条中显示；区块由用户定义，并支持跨已保存词条的批量更新。以下内容尚未进入 `spec/`；接受后需要新增 BDR、响应契约与设置页。

本轮起，本文取代 [`spec/.discovery/dictionary-sources.md`](../spec/.discovery/dictionary-sources.md) 的「本地词典优先」方向。那份文件保留为研究记录：以后若接入系统词典或导入词库，可以作为另一种内容来源加入，不必改区块模型。

## 区块是什么

区块是词条的一节。由用户定义，应用不自带任何区块。

| 字段 | 含义 |
| --- | --- |
| `id` | 一次性生成的稳定标识，模型回复里原样带回。 |
| `title` | 查词卡与词条里显示的标题。用户文本，不翻译。 |
| `instruction` | 让模型写什么，例如「给出两个例句，使用该词的语言，每句后附词条释义语言的解释」。 |
| `enabled` | 关闭的区块不请求、不显示。 |
| `order` | 各节出现的顺序。 |

内容是带换行的纯文本；应用不渲染 Markdown、表格或图片。需要列表的说明就一行一条。

没有默认区块，没有预设标题。设置页空状态只把一条示例说明当作占位提示，用户自己写内容。Add 菜单是否提供可插入的模板，见决策 1。

## 显示在哪

- **查词卡。** 现有释义之后，每个启用的区块一节：标题，然后正文。卡片保持 320 pt 宽；内容长时整节可折叠（决策 2）。卡片现有规则不变：查词不收藏，关闭卡片即离开。
- **生词本词条详情。** 同样的区块放在词条释义与语境之后，完整显示。生成结果随词条保存，离线可读。

两处读同一份结果：在卡片里生成后再收藏，区块随释义一起进入词条。

## 何时生成

普通查词永不自动生成。

- **单个词。** 卡片与词条详情各有「生成区块」入口，为该表达发送一次请求，包含全部启用的区块。
- **批量更新。** 生词本已支持多选，工具栏增加「更新区块」；设置页可提供「更新全部已保存词条」。两者都先确认并写明请求数，顺序执行、显示进度、可停止，逐条报告失败。更新失败的词条保留原有内容。
- **说明改动之后。** 修改区块的 instruction 不会自动改写已保存内容。用旧说明生成的内容标为「已过期」，并提供重新生成；批量更新会清掉过期标记（决策 3）。

成本是明确的：每个表达一次请求，包含全部启用区块；对 N 个词条批量更新就是 N 次请求。确认框写明这一点，任何生成都不静默发生。

## 请求与契约

与查词请求分开，区块失败绝不会带走释义：

```json
{
  "expression": "bank",
  "language": "en",
  "lemma": "bank",
  "part_of_speech": "noun",
  "meaning": "河岸；银行",
  "context": "We sat on the bank of the river.",
  "definition_language": "zh-Hans",
  "blocks": [
    {"id": "3F2A…", "instruction": "Give two example sentences…"}
  ]
}
```

回复是一个 JSON 对象：

```json
{"blocks": [{"id": "3F2A…", "text": "1. …\n2. …"}]}
```

校验沿用现有契约规则：

- 只有一个对象，没有多余键。
- 返回的 id 恰好等于请求中启用的 id：不缺、不重、不新增，否则为 `format`。
- `text` 是字符串；空字符串合法，表示这个词没有可说的，这一节隐藏而不显示空标题。
- 无法校验原文或目标语言：区块是用户自己问题的回答。说明要求中文就得到中文；应用不猜区块该用什么语言。
- 与学习、查词一样，`format` 失败给一次纠正机会。
- 区块请求独立于查词请求：失败、取消或未配置模型都不影响卡片里的释义与词条已保存的内容。

区块说明属于 System Prompt；表达、释义与语境是数据，沿用现行的注入规则。说明与生成内容都不进入 `strings/translations.json`。

实现前需定下上限：每次请求的启用区块数、单条说明长度、说明总量；超限明确拒绝，不截断。

## 存储

- 只在查词卡生成的结果留在现有内存查词缓存里，与释义一致。
- 收藏的词条把区块存进词条：区块 id、正文、说明指纹（说明文本的哈希）、释义语言、生成时间。标题实时读取设置。
- 指纹不一致时标为过期，旧正文仍显示。
- 释义语言或词条语言变化不会静默重新生成（决策 4）。

## 设置

新增设置页「词条区块」（界面名称见决策 5）：

- 区块列表：标题、说明、开关、拖动排序、添加、删除。
- 空状态解释这个功能，并用占位提示展示一条示例说明。
- 「更新全部已保存词条」，确认框写明数量。
- 删除区块时询问已保存内容怎么处理（决策 3）。区块内容不发送到任何地方；它只存在于词条与内存查词缓存里。

## 需要人决定

1. **模板。** 不提供可插入示例（建议，符合「用户自己定义，不是提前设置好」），还是在 Add 菜单里提供可编辑的模板。
2. **卡片长度。** 卡片里长区块默认折叠（建议），还是让卡片继续变高。
3. **删除区块与过期内容。** 区块删除后保留已存正文但不再显示，过期正文只标记不删除（建议）；另一种是立即删除内容。
4. **语言变化。** 已生成的区块保持原样，直到用户重新生成（建议），还是在释义语言变化时自动重新生成。
5. **界面名称。** 设置页与卡片入口叫「区块」「Sections」还是「词典」；这决定新增的本地化字符串。

## 必须实测

- 模型在用户自定义说明下的真实表现——尤其是长说明、混合语言说明，以及与「只回 JSON」冲突的说明。
- 多个区块时的 token 成本与延迟，以及一个真实生词本规模下批量更新的耗时。
- 只支持 `json_object` 的服务（DeepSeek）能否像守住查词键一样守住区块 id。
- 卡片里长纯文本区块的可读性，折叠是否足够。
- 「已过期」是否可理解，用户是否会真的执行批量更新。
