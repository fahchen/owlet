# 意图：翻译目标映射

状态：已实现（T26，2026-10-04）。行为规格见 [BDR-0003](../spec/settings/decisions/BDR-0003-translation-target-mapping.md) 与 [target-mapping.feature](../spec/settings/features/target-mapping.feature)。

## 一句话

让翻译的目标语言跟着原文语言走，用户不必再记得当前目标是什么。

## 复述

- **结果**：发请求前在本地检测源语言，按用户配置的「源语言 → 目标语言」映射决定目标；未命中或无法识别时用兜底目标。
- **用户**：本人。中文母语，双向使用——读英文／日文时要中文，写英文时要把中文草稿转过去。
- **为什么现在**：目标语言目前是一个全局会话状态，由用户自己维护。每次反向翻译都要「先发现方向不对、再切目标、再重新触发」，而这发生在注意力已经投入写作的时候。忘记切换时结果是错方向的（中文草稿被译成中文），用户看到文本没变化，容易误以为模型没工作。
- **成功**：方向跟着文本走，用户不再需要记得当前目标；手动指定语言仍可持久覆盖；旧设置迁移为兜底目标。
- **约束**：只改翻译的目标解析。润色保持原文语言（只补一条混写规则）；快捷键三条固定不动；LLM 契约与返回校验不变；语言选项取自系统，不维护应用自有清单。
- **不做**：按对快捷键、leader 式快捷键、润色映射、预置任何映射行。

## 关键判断

- **价值只在双向用户身上成立**。只做单向翻译的人零收益，还多出「检测判错」这个新的失败模式。本项目的实际使用频率高，价值成立。
- **唯一无法被更轻方案替代的部分**：一个「互换方向」按钮能解决「我发现方向错了，想翻过来」，但解决不了「我根本不会发现方向错过」。
- **映射表初始为空**，由用户逐条添加；兜底目标独立设置，默认 `zh-Hans`。表为空时行为与今天完全一致。
- **润色的混写**由 Prompt 保证：不翻译、不转写、不归一化任何片段；不把本地检测结果传给润色。
