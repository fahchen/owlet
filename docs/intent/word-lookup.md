# 意图：查词卡（第一步）

状态：设计结论已确认（2026-10-07 Suikou 审阅）。第一步的 12 项产品选择已转为正式规格与实施计划；当前无待用户裁决的产品问题，见「Open questions」。未做原生验证、未启动实现。本文保留讨论与备选；行为以 [查词规格](../../spec/vocabulary/features/word-lookup.feature) 与 [BDR-0008](../../spec/vocabulary/decisions/BDR-0008-reading-word-lookup.md) 为准。

本次讨论只做**第一步**（阅读场景里的查词卡：解释 + 发音，以单词为主，兼容明确选中的短语／整句），**第二步**（输入框查询、写回生词本、查询历史等）留到之后。

相关既有信号：`spec/vocabulary/decisions/BDR-0006-on-demand-enrichment.md`（生词本详情页按需补读音／词性，已接受待实现）、`spec/learning/decisions/BDR-0005-definition-language.md`（释义语言跟随翻译目标）、`docs/vocabulary-schema-v2.html`（生词本 v2 结构）。本文与它们互补，不重复定义生词本内部行为。

## 一句话

在阅读的当场——浮窗、文本处理页、生词本详情、历史详情、学习表达式——把不认识的词点开或选中后查询：看到读音、听到发音、看清语境中的意思，不打断阅读，也不强制收藏。跨句复用时明确显示旧语境来源，只有按当前语境重查后才把解释呈现为本句意思。

## 分步

1. **第一步（本文）**：只读正文单击单词，或选中后点击工具栏「查询」／右键「查询所选」 → 弹出查词卡（读音 + 解释 + 系统 TTS 发音）。学习行保留点击收藏，通过选中后的工具栏／右键查询。不加入生词本、不加输入框、不引入外部词典服务。
2. **第二步（不在本文）**：查询输入框、查询结果写回／生成生词本条目、按语言与词形整理查询记录、可能的外部词典音频。

## 既有结论与审阅修订

### 1. 触发方式：单击单词，或选中后明确查询

```gherkin
Rule: 查词只由明确动作触发，选中本身不发起请求

  Scenario: 单击查询单词
    Given 文本以只读方式显示
    When 用户单击单词 "running"
    Then 弹出该词的查词卡
    And 不改变光标之外的其他文本外观

  Scenario: 右键查询选中的任意文本
    Given 用户在译文里选中了一段文字
    When 用户右键并选择「查询所选」
    Then 弹出查词卡，内容以选中文本为单位
    And 卡片把所在句子作为上下文
    And 用户若不选该项，则不发起任何请求

  Scenario: 拖拽选中显示查询工具栏
    Given 用户从 "running" 拖拽到 "quickly"
    Then 这一段仍被选中，可供复制与收藏
    And 显示含「查询」动作的选区工具栏
    And 不自动弹出查词卡
    And 不自动发起请求
    When 用户点击工具栏的「查询」
    Then 弹出查词卡，查询范围就是选中的文本

  Scenario: 不重复发起同一选中
    Given 已有一次查词结果
    When 用户在相同语境、相同查询设置下再次查询同一选中
    Then 直接展示已有结果，不发起新请求
```

- **选区工具栏（Suikou 首轮已确认）**：选中有效文本后显示工具栏，点击其中「查询」才打开查词卡／发起请求；右键「查询所选」保留。工具栏与右键均支持单词、短语、整句，不自动扩大用户选区。
- 单击单词保留为只读正文的快路径；选区工具栏增加查询入口，不意味着取消单击查词。更换或取消选区后，工具栏不能查询旧选区。
- **单击查词意味着放弃"在只读文本里用无修饰键单击放置光标"**。这是明确接受的代价：拖拽选中、双击选词、⌘C 全部保留。
- 选中只显示操作工具栏，不自动弹查词卡、不自动请求。工具栏与查词卡是不同界面，不能混称「自动弹卡」。
- **适用边界**：单击快路径针对只读阅读正文。文本处理页的原文输入框、生词本编辑字段仍保留编辑行为，不能直接改成只读。
- **学习行例外（2026-10-07 已确认）**：保留点击收藏／取消收藏（T45），点击文字不触发查词。学习行查词通过选中后的工具栏「查询」或右键「查询所选」触发；拖拽选中不得误触收藏。该区域不提供单击查词快路径。
- 单击与双击存在手势竞争：不能在第一次按下时立即请求，再把第二次点击解释为选词。实现前须验证拖拽／双击的识别与单击延迟；未验证前不承诺既零延迟查词又完全保留双击行为。

### 2. 悬停反馈：系统选中色降透明度 + I-beam

```gherkin
Rule: 悬停反馈是"可操作"的预告，不是选中态

  Scenario: 悬停可查单词
    Given 正文以系统正文色显示
    When 鼠标悬停到单词 "running" 上
    Then 该词显示系统选中色的淡化版本作为背景
    And 光标保持 I-beam
    And 不改变字号、字重、字距与行高
    And 背景只覆盖词本身，不延伸到空格
    When 鼠标移开
    Then 背景消失且段落布局不位移
```

- 取值：`NSColor.selectedTextBackgroundColor` 约 25–35% 不透明度；深浅色共用同一语义色，不为深色单独调数值。
- 不加圆角、边框、内边距；不使用 `.quaternary`（会被读成"荧光笔标记"而非"可操作"）。
- 不用 pointing hand 光标（手型属于"链接跳转"，与"查解释"语义不符）。
- 悬停背景只在该词**尚未被选中**时显示，避免与拖拽选中叠两层背景。
- 该方向已写入 `spec/DESIGN.md` 的封闭例外，待原生验证：仅系统选中色淡化的悬停背景，不扩展至自定义色值、圆角、边框或阴影。
- 25–35% 只是候选值，不能保证辅助功能下可见。验收以原生浅／深色及提高对比度状态为准；HTML 样例只能辅助比较，不能证明 AppKit 表现。
- 悬停只是辅助反馈；键盘与 VoiceOver 用户也须能明确触发查询，不依赖鼠标悬停。下划线 + 手型不再列为随手替换项：它既偏离已确认语义，也触及现行设计约束。

### 3. 技术路线：统一行为，控件替换先验证

审阅修正：逐词悬停与单击需要定位字符／词范围；仅用现有 `Text` + `.textSelection(.enabled)` 不足以提供这套行为，但这不构成「五处必须一次全换控件」的证明。`NSTextView` 是优先验证的原生候选，不是已完成可行性验证的方案。

- 五处阅读场景仍是目标覆盖范围：浮窗、文本处理页只读结果、生词本详情只读内容、历史详情、学习表达行。可编辑区域不在自动替换范围。
- 复用查询行为与卡片，不要求每个区域使用相同的展示控件。已有 `PanelJustifiedText` 使用 `NSTextField`；逐句对照由 `AlignedSegments` 展示，需要保留各自布局，而非从零另造同功能组件。
- 旧文引用的 `TextSelection.current()` 在现仓库中不存在，删除「与已有选中读取同源」的假设。单击查询不必先改变系统选区；点击词范围、局部语境、锚点与菜单查询的选区读取都需验证。外部应用选区桥接与此是不同边界。
- 原生验证至少涵盖：词命中（空白、行末、标点不能误命中相邻词）、换行／两端对齐、拖拽／双击、⌘C、选区工具栏与右键菜单、动态高度、键盘／VoiceOver、popover 焦点及浮窗关闭行为。工具栏采用原生组件；先验证一个只读区域，再决定其余区域如何接入。

### 4. 查词走 LLM，带上当前语境

```gherkin
Rule: 查词请求带上词与它所在的句子

  Scenario: 上下文随请求发送
    Given 用户在译文里查询 "bank"
    And 本次查询未复用其他语境的结果
    Then 请求里带上该词与包含它的当前句子
    And 返回结果显示该词在本句中的意思
```

审阅补充：

- 「所在句子」只是单词／句内短语的常见情形。跨句选中时，语境必须覆盖整段选中；无标点、标题等不能强凑一句。建议由应用截取覆盖选中的局部语境，不默认发送整篇正文。
- 应用保存查询文本、它在语境中的范围及此次请求身份。原形不必出现在语境中；需匹配的是用户实际选中的词形。
- 返回结构与请求对应关系可本地校验；释义正确、原形正确、读音准确则不能靠 JSON 校验保证。语言标签匹配也不能证明解释实际使用了该语言。
- **释义粒度已确认**：只解释文中义，必要时附词性与用法；不强制增加通用义或完整多义项。
- **释义语言已确认**：沿用 BDR-0005，翻译用本次目标语言，润色按原文语言查目标映射，未命中用兜底目标；历史／学习承接来源规则，生词本用条目已记的释义语言。不另设查词释义语言选择器，接受英释英。
- **无原句语境已确认**：只提供表达、缺少原句时查询一般含义，卡片标明「无原句语境」；不让模型编造原语境。

### 5. 读音与音标

- 发音**先走系统 TTS**（`AVSpeechSynthesizer`），不引入外部词典音频服务。修正「离线、零成本、即时」的绝对承诺：不产生外部词典 API 费用；可用语言、语音资源与首次播放延迟须在目标系统验证，不把下载额外语音列为查询前提。
- 「读音」不等于「拼音／音标」：英语可用 IPA、日语假名、中文拼音。建议复用 BDR-0006 的读音体系；体系属于请求条件，而非由模型随意决定。
- 读音由模型给出，本地只校验约定的结构与空值，不声称可验证音韵正确性。模型不确定时允许留空；读音缺失不使有效释义失败。
- 建议 TTS 朗读用户查询的词形，模型读音仅供阅读，不把 IPA／假名字符串直接作为朗读文本。孤立词的 TTS 发音可能与句中异读不一致，不宣称它是语境读音的权威音频。
- **无可用语音已确认**：保留发音按钮，禁用并说明「暂无系统语音」，不阻塞释义。文本语言未知时也不凭页面语言硬选发音。
- **发音行为已确认（第二轮 11A）**：打开卡片不自动发音，用户点击才播放；下一次播放中断旧音，关闭／切换卡片时停止。按文本语言选可用系统语音，不新增语音偏好设置；读音体系配置与系统语音选择是两件事。

### 6. 词形：显示选中的词，关联到原形

- **原形来源已确认**：由 LLM 返回原形，本地不猜测屈折归一化。点 `running` 时，卡片显示选中的 `running`，并关联模型返回的 `run`。
- 原形可能未知，也可能不适用于短语／整句；允许缺省，不能为凑字段编造。相同词形与原形不重复显示。
- **标题已确认（第二轮 10A）**：查询词形作标题，原形不同时作次级信息。

### 缓存方案的必要纠错

- 原建议 `lemma + language + 语境指纹` 不可直接用作首次请求键：`lemma` 查询前未知；包含语境又宣称「跨句命中」也混淆了精确缓存与另一层跨句检索。第一步不预建原形索引。
- 精确命中按**实际查询文本 + 局部语境 + 所选范围（相对语境）+ 释义语言 + 读音体系 + 影响结果的模型／请求配置版本**复用，已知文本语言也纳入。保留大小写等会改变词义的信息；配置标识不含 API Key。
- **跨句复用已选 4B**：精确记录不存在且有兼容旧语境记录时，展示同词的旧语境解释，明确标注「这条释义来自另一句」并展示来源语境，提供「按当前语境重查」。展示旧解释不自动请求；没有可复用结果时，本次明确查询才发起新请求。
- 跨句候选须有真实来源语境，并匹配已知相同文本语言、相同查询词形及相同解释设置；无原句的一般解释仅按无语境条件精确复用，不标成「来自另一句」。不能凭未知词形猜原形。LLM 返回的原形是结果信息，不要求为查缓存额外请求模型。需要扩大到不同词形的复用时另行确认。
- 同条件请求进行中时复用进行中状态，不重复发送；成功结果可跨阅读区域复用，不能因此变成持久查询历史。设置改变后的新查询不复用旧配置结果。
- 同一失败查询再次打开先展示失败，只有明确「重试」才重发；不同语境是新查询。失败状态不落盘，也不永久阻止后续查询。
- **缓存寿命已确认（第二轮 9A）**：第一步只做有容量上限的内存缓存，退出应用清空，不持久化。跨句候选查找与精确命中分别处理，不把旧语境解释存成新语境结果。
- 按当前语境重查成功后，保存为当前语境结果；明确刷新只替换同条件旧结果，不覆盖来源句记录。失败保留可用旧结果，并保留其来源标识及本次失败提示。

### 独立查词契约的最小边界（已落规格，待实现）

- 请求输入：实际查询文本、应用截取的语境与所选范围、已知的文本语言线索、明确的释义语言、读音体系。`lemma`、读音、词性与义项属于模型输出，不作为必填请求输入。
- 返回：对应的查询文本、文本语言（允许未知）、释义语言、解释；原形／读音／词性仅在适用且确定时提供。短语／整句用同一卡片，不强求词的字段；遵循 BDR-0006 对整句不展示读音与词性的边界，TTS 仍可朗读查询文本。
- 应用校验返回对应此次选中、语言标签与结构符合契约；语境及范围以本地请求快照为准。失败只影响查词卡，允许重试，沿用隐藏调试页的诊断与不记录 Key 的要求。
- 释义语言与文本语言是两项，不合并为一个 `language`；前者控制解释，后者用于表达标识及 TTS。混写／未知语言时不凭页面语言硬选发音。

### 实现边界与验证

- 读音体系复用 BDR-0006；不将模型读音字符串当作系统 TTS 的音素输入。
- 一次展示一张卡片。查 A 后立即查 B，A 的迟到响应不得覆盖 B；关闭卡片或离开页面后不得被旧响应重新弹开。
- 卡片靠近所查文本，保留可复制选区；须验证工具栏／popover 不会误触发浮窗失焦关闭。Esc 先关闭查词卡并恢复正文焦点，再次 Esc 按原有浮窗规则处理。
- 键盘可对已选文本触发同一查询动作，VoiceOver 有可发现的动作与加载／失败反馈；具体承载方式随原生验证确定。
- 无选中、仅空白或标点不发请求。跨句选中不能截断后仍假称在解释全部选中；最大输入与语境长度及超限提示在实现前定下。
- 是否把查词结果用于更新生词本，完全留在第二步；第一步不覆写已有释义，不新增自动入库路径。
