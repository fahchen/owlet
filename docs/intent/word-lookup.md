# 意图：查词卡（第一步）

状态：设计进行中（2026-10-04 起）。本次讨论只做**第一步**（每个阅读场景里对单个生词的查词卡：解释 + 发音），**第二步**（输入框查询、写回生词本、跨场景查询历史等）明确留到之后，不在本文范围。

相关既有信号：`spec/vocabulary/decisions/BDR-0006-on-demand-enrichment.md`（生词本详情页按需补读音／词性，已接受待实现）、`spec/learning/decisions/BDR-0005-definition-language.md`（释义语言跟随翻译目标）、`docs/vocabulary-schema-v2.html`（生词本 v2 结构）。本文与它们互补，不重复定义生词本内部行为。

## 一句话

在阅读的当场——浮窗、文本处理页、生词本详情、历史详情、学习表达式——把不认识的词点开：看到读音、听到发音、看清它在**这一句里的意思**，不打断阅读，也不强制收藏。

## 分步

1. **第一步（本文）**：每个场景里单击单词或右键查询所选文本 → 弹出查词卡（拼音 + 解释 + 系统 TTS 发音）。不加入生词本、不加输入框、不引入外部词典服务。
2. **第二步（不在本文）**：查询输入框、查询结果写回／生成生词本条目、按语言与词形整理查询记录、可能的外部词典音频。

## 已确认的决定

### 1. 触发方式：单击单词，或右键「查询所选」

```gherkin
Rule: 查词只由明确动作触发，选中本身不发起请求

  Scenario: 单击查询单词
    Given 文本以只读方式显示
    When 用户单击单词 "running"
    Then 弹出该词的查词卡
    And 不改变光标之外的其他文本外观

  Scenario: 右键查询选中的任意文本
    Given 用户在译文里选中了一段文字
    When 用户右键并选择「查询所选」
    Then 弹出查词卡，内容以选中文本为单位
    And 卡片把所在句子作为上下文
    And 用户若不选该项，则不发起任何请求

  Scenario: 拖拽选中不影响查词
    Given 用户从 "running" 拖拽到 "quickly"
    Then 这一段仍被选中，可供复制与收藏
    And 不自动弹出查词卡

  Scenario: 不重复发起同一选中
    Given 已有一次查词结果
    When 用户用同一段选中文本再次查询
    Then 直接展示已有结果，不发起新请求
```

- 触发收敛为两条明确动作：单击单词是快路径，右键「查询所选」是通用路径（支持短语、整句）。
- **单击查词意味着放弃"在只读文本里用无修饰键单击放置光标"**。这是明确接受的代价：拖拽选中、双击选词、⌘C 全部保留。
- 选中即自动弹卡已被否决：会与「拖拽选中 → 收藏」打架，且违背项目"不自动发请求"的既有取向。

### 2. 悬停反馈：系统选中色降透明度 + I-beam

```gherkin
Rule: 悬停反馈是"可操作"的预告，不是选中态

  Scenario: 悬停可查单词
    Given 正文以系统正文色显示
    When 鼠标悬停到单词 "running" 上
    Then 该词显示系统选中色的淡化版本作为背景
    And 光点保持 I-beam
    And 不改变字号、字重、字距与行高
    And 背景只覆盖词本身，不延伸到空格
    When 鼠标移开
    Then 背景消失且段落布局不位移
```

- 取值：`NSColor.selectedTextBackgroundColor` 约 25–35% 不透明度；深浅色共用同一语义色，不为深色单独调数值。
- 不加圆角、边框、内边距；不使用 `.quaternary`（会被读成"荧光笔标记"而非"可操作"）。
- 不用 pointing hand 光标（手型属于"链接跳转"，与"查解释"语义不符）。
- 悬停背景只在该词**尚未被选中**时显示，避免与拖拽选中叠两层背景。
- 这条是 `spec/DESIGN.md`「不用自定义颜色」的**明确例外**，需在规格里写成封闭条款：允许系统 `selectedTextBackgroundColor` 的淡化版作悬停背景，不得使用自定义色值、圆角、边框或阴影。
- 尚未做的裁决：实际截图对比（`design/index.html` 内联样例数据），确认 25–35% 是否够可见。可再试的变体：下划线 + 指针、或提高不透明度。

### 3. 技术路线：统一换成只读 `NSTextView`

"逐词悬停"和"单击某词"都要求逐词命中测试；SwiftUI `.textSelection(.enabled)` 的 `Text` 是整块一个视图，做不到。因此建议**五处正文统一换成只读 `NSTextView`**（保留系统字体、系统色、可选中）：

- 浮窗原文／译文、文本处理页原文／译文、生词本详情、历史详情、学习表达行。
- 一套实现，行为一致，不会出现"浮窗能点、别处不能点"。
- 右键「查询所选」直接读 `selectedRange()`；单击查词复用同一份选中文本读取逻辑（与现有 `TextSelection.current()` 同源）。
- 尚未评估：区域排版（字号、行高、对齐）需逐个回归验证。这是本功能最大的工作量。

### 4. 查词走 LLM，带上当前语境

```gherkin
Rule: 查词请求带上词与它所在的句子

  Scenario: 上下文随请求发送
    Given 用户点击译文里的 "bank"
    Then 请求里带上该词与包含它的当前句子
    And 返回结果显示该词在本句中的意思
```

### 5. 读音与音标

- 发音**先走系统 TTS**（`AVSpeechSynthesizer`，离线、零成本、即时），不引入外部词典音频服务。
- 音标由模型给出（不保证权威，本地只做格式校验，模型不确定时允许留空，不编造）。
- 发音语音按 `language` 选系统默认语音；无可用语音时的呈现（置灰／隐藏／提示去系统设置）**未决定**。
- 同一语言是否要在设置里选语音**未决定**（BDR-0006 已有"读音体系按语言配置"的思路，可复用其"语言"分组）。

### 6. 词形：显示选中的词，关联到原形

- 点 `running` 时，卡片显示选中的 `running`，并关联到原形 `run`（原形由模型返回，本地不做屈折归一化校验）。
- 原形／选中的词形在卡片上的具体排版（标题写选中词、副标题给原形，还是相反）**未决定**。

## 未决问题（下次从这里继续，问到哪答到哪）

按优先级：

1. **中文切词**：英文靠空格，"单击单词"在中文里要先定义"词"是什么（单字？系统分词？整段？）。这是单击查词在中文文本上的直接阻塞项。
2. **模型契约形态**：查词是新增独立 `$defs.lookup` 契约与请求，还是在现有 `learning` / 释义请求上扩字段。查词请求的字段至少需要：`headword`（选中词）、`lemma`（原形）、`language`、`reading`、词性、一个或多个义项、`context` 校验（词必须出现在语境句中）。
3. **缓存**（已给出建议，待拍板）：
   - 建议键：`lemma + language + 语境指纹`。命中时：同句重复点击零请求；换句子仍可命中，但卡片必须显示"这条释义来自另一句"，并提供「按当前语境重查」；不自动发起新请求。
   - 建议重查直接覆盖旧条目，不并存多份。
   - 建议失败不写缓存，但在内存里记一次失败：同一词同一语境再点不自动重发，卡片显示失败与「重试」。
   - 待定：缓存持久化（SwiftData 落地）还是先只做内存版。**建议第一步先内存版**，持久化随第二步（写回生词本）一起定。
4. **释义粒度**：只要"文中义 + 一个通用义"，还是完整多义项（按词性分行）。多义项对生词更有用，但请求更长、契约字段更多。**建议多义项**。
5. **卡片标题排版**：选中词形与原形谁做主标题（承接上面的第 6 条决定）。
6. **改写回生词本**：查词卡的释义是否写回条目已有 `meaning`（目前只在收藏时填一次，之后不更新），还是两套并存互不覆盖。**建议不覆盖**，第二步再议。
7. **TTS 细节**：连点两个词时是否中断上一个发音；无语音语言如何呈现。
