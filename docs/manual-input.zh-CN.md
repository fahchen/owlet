# 浮窗内的手动输入

状态：已实现（2026-10-23）；四个待定决策在 [BDR-0018](../spec/processing/decisions/BDR-0018-manual-input-in-panel.md) 裁定，均采用下文的建议。本文其余部分是设计记录。

## 今天的行为

- 触发时读不到选区（`.unreadable`，密码框也归入这一类）会显示紧凑提示「无法读取任何文字」，入口是「输入文本」（`PanelController.swift:48`、`:169`）。选择后浮窗关闭，主窗口的翻译页打开，原文是一个可编辑的 `TextEditor`（`PanelRootView.swift:147`、`OwletApp.swift:303`、`TextProcessingView.swift:161`）。
- 缺少辅助功能权限是另一条紧凑提示，入口是「权限设置」（`PanelController.swift:165`）。
- 读取成功时原文进入输入框并发起请求，浮窗展开——今天是收到第一段流式内容或完整结果时展开（`PanelController.swift:150-163`）。
- 展开后的浮窗原文本来就可编辑（`ExpandedPanelContent.swift:41`）。逐句对照下，成功结果会把原文折叠成句对（`ExpandedPanelContent.swift:51`）。
- 产品定义写得很明确：读取失败显示紧凑提示与手动输入入口，输入在完整窗口进行；替换不会自动展开输入界面（`spec/product.md:23`、`:30`、`:61`）。BDR-0002 给出了理由：展开前遇到的阻断不需要展示无法使用的处理界面。

## 提案

### 1. 读不到文字：浮窗本身就是编辑器

读不到内容的触发直接进入手动输入模式，就在快捷键已经打开的浮窗里：

- 浮窗展开，原文为空且可编辑，光标就位。不发起请求，`selection` 保持 nil。
- 内容区保留今天的措辞（「无法读取任何文字」）作为说明，不带操作按钮：编辑器就是出路。
- 占位提示与 ⌘↩ 沿用页面现有的（`spec/DESIGN.md:64`）；原文为空时 ⌘↩ 不做事，与主窗口现有行为一致。
- Esc 关闭并丢弃文字，与今天未完成的浮窗一致。
- 替换快捷键没有可写回的选区，因此沿用现有规则：手动输入永不写回（`spec/product.md:30`）。

这不违背 BDR-0002 的本意：它拒绝展示的是「等着设置或重试」的界面。这里的界面本身就是解决办法——一个输入框——展示它就是最短路径，而不是死胡同。权限与配置失败保留紧凑提示，正因为它们的出路是设置。

### 2. 有文字：显式的编辑入口

- 紧凑态原文条增加一个铅笔控件（「编辑文本」）：展开浮窗，聚焦原文编辑器，光标放在末尾。展开后点原文本来就能编辑；这个控件让它可被发现，也能在第一段内容到达前就用上。
- 展开态不需要新控件：原文今天就可编辑。
- 逐句对照下，成功结果会把原文折叠起来。进入编辑时必须重新显示原文框及其现有文字，直到文字改变或浮窗关闭（决策 4）。
- 不提议「新文本」清空动作：清空是破坏性操作，⌘A 加删除已经能做，目前也没有需要它的证据（决策 2）。

## 状态一览

| 触发结果 | 今天 | 提案 |
| --- | --- | --- |
| 读不到文字，或密码框 | 紧凑提示 +「输入文本」→ 主窗口 | 浮窗展开为空编辑器；内容区保留说明 |
| 缺少辅助功能权限 | 紧凑提示 +「权限设置」 | 不变（决策 1） |
| 读到选区 | 紧凑 → 请求 → 第一段或结果到达时展开 | 不变 |
| 用户想改原文 | 展开后点原文；逐句对照下被折叠 | 紧凑条上的铅笔；折叠规则见上 |

## 不变的部分

- 原文为空或全空白不发起模型请求；没有 `Selection` 就不写回。
- 手动输入在历史里没有来源 App（[BDR-0007](../spec/history/decisions/BDR-0007-history-as-learning-log.md)）。
- 失败提示、重试与「出错时保留已展开工具栏」的形态。
- 主窗口仍是阅读与编辑长文本的地方；本提案只去掉空内容场景里的一次窗口切换。

## 接受后要改的规格

- `spec/product.md:23`、`:30`、`:61`：「紧凑提示 + 完整窗口手动输入」改为「浮窗展开为编辑器」；不写回的规则保留。
- BDR-0002 增加例外，或由新 BDR 记录：能接受输入的编辑器不属于无法使用的界面。
- `translation.feature` 与 `replacement.feature` 的手动输入场景改写为新入口。
- 提示消失后，`Notice.actionTitle` 不再需要 `.unreadable` 的「输入文本」。

## 需要人决定

1. **权限失败。** 保留紧凑的权限提示（建议：它有一键修复，铅笔仍可进入手动输入），还是同时展开带权限说明的编辑器。
2. **有文字时。** 只加铅笔（建议），还是再加一个清空原文的「新文本」动作。
3. **手动输入放在哪。** 浮窗（建议）还是今天的主窗口。若选浮窗，决定主窗口入口是否保留为次要的「在窗口中打开」。
4. **成功后的逐句对照。** 进入编辑时重新显示被折叠的原文（建议），还是这一次运行切回分区布局。

## 必须在真机上核对

- 全局快捷键后的焦点：浮窗取得按键，编辑器拿到 first responder，快捷键与输入法状态不受影响。
- 原文为空时浮窗的高度与布局；说明读起来像解释而不是错误。
- 逐句对照下编辑时的折叠与展开。
- Esc、⌘↩，以及编辑器为空时的复制入口。
- 落到这里的替换触发：结果仍可复制，且没有写回任何地方。
