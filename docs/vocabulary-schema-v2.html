Owlet · SwiftData · schema v2 提案

生词本库重新设计

为长期收藏与后续扩展重做的 schema。保留现有唯一键与级联语义，把「一个表达」拆成身份、释义、遇见三层，让音标、词性这类字段各就各位，而不是往 VocabularyEntry 上不断糊新列。现状文档见 docs/data-shapes.html。

混合扩展策略 单条释义，留 sense 扩展位 历史表不动 一次数据迁移，其余全是加列

三个设计决定

按你的选择定下来，后面整个 schema 都从这三条推出来。

你的选择

混合扩展

音标、词性、词频这类高频字段给独立列——可查询、可排序、类型安全。长尾字段（词源、变位表）丢进一个 JSON 列。

你的选择

先单条释义，留扩展位

现在仍是一条释义。但释义相关的列全部搬到独立的 VocabularySense 表，一条表达恰好挂一条 sense——以后要多义项，多插一行即可，不迁移已有数据。

你的澄清

学习本 = 历史记录

不新建「学习本」模型。HistoryRecord 保持原样，只补一个计数列，让「这次翻译贡献了几个生词」可见。

字段命名

改名原则：名字说清是什么而不是从哪来；Bool 带 is 前缀；同一个概念在三张表里用同一个词；避免与 HistoryRecord 已有列撞义。

表关系

三层：Entry 是身份（什么词、哪种语言），Sense 是释义（什么意思、什么词性），Context 是遇见（在哪句话里见过）。音标挂 Entry——同一个词不同义项通常共享读音；record 这种名动读音不同的，由 Sense 自己的 pronunciation 覆盖。

无外键 · 独立表
为什么把 sense 拆出来，而不是先留几个空列

如果把 definition、partOfSpeech 直接放 Entry 上，以后要支持多义项就得：建 Sense 表、写迁移把每行那几列搬过去、改所有读取点。拆在前面，这笔迁移永远不用做，代价只是今天多一张表和一次 senses.first。

这是「先单条，留扩展位」的唯一诚实实现：扩展位不是预留空列，是预留基数。

VocabularyEntry

只管身份与整词级属性。唯一键、trim 规则、级联语义与现版本一致，已有数据无需转换。

扩展策略

「以后加字段」具体怎么加——按这个顺序判断，避免 attributes 变成垃圾桶。

需要筛选 / 排序 / 唯一性

升格成独立列

词频、难度等级、下次复习时间。加一个可空列，SwiftData 对新增可空列是自动迁移。

只展示，不查询

放 attributes JSON

词源、同义词列表、变位表。用 Codable struct 编解码，不要裸 Dictionary。

一条表达有多个

挂到 Sense 或建子表

多义项已由 Sense 承接。复习记录这种「一对多且持续增长」的，建独立表，不要塞数组列。

// attributes 的类型安全用法：永远经 Codable，不裸 Dictionary
struct EntryAttributes: Codable {
    var etymology: String?
    var synonyms: [String]?
    var inflections: [String: String]?
}

extension VocabularyEntry {
    var decodedAttributes: EntryAttributes {
        get { attributes.flatMap { try? JSONDecoder().decode(EntryAttributes.self, from: $0) } ?? EntryAttributes() }
        set { attributes = try? JSONEncoder().encode(newValue) }
    }
}
attributes 的使用纪律

一旦 attributes 里某个字段需要「找出所有 X 的词」，它就必须升格成独立列。JSON blob 在 SwiftData 里无法建谓词查询——写进去容易，查出来要全表扫描后在内存里过滤。

判断标准只有一条：这个字段会出现在筛选器、排序键或统计里吗？会 → 独立列。不会 → attributes。

落地顺序

每一步都是能独立编译、独立发布的提交，不预建下一步要的东西。

迁移路径 plan 建议
1

拆出 VocabularySense

建表，把 meaning 搬成单条 sense，Entry 上留 definition 计算属性代理。这是唯一需要写数据迁移的一步——先做完，后面全是加列。

2

加读音三件套

pronunciation、pronunciationScheme 加 Sense 的覆盖列。可空列，SwiftData 自动迁移。先只做展示，填充靠手动编辑。

3

让 LLM 返回读音与词性

扩 learning 契约的 item schema，加两个可选字段。模型不返回时保持 nil，不阻塞收藏。

4

加 tags / isStarred / userNote

纯本地字段，不碰 LLM。配套做筛选器与编辑界面——没有界面的字段等于不存在。

5

加 capturedFrom / capturedAppID，导出升 v2

来源追溯。放最后因为它纯属锦上添花，前面四步才是你每天会用到的。

没放进来的东西

复习调度（SM-2 间隔重复、复习日志表）——你在选项里没选它，所以一列都没加。真要做时它是独立一张 ReviewLog 表加 Entry 上几个调度列，与这版 schema 不冲突。

牌组 / 收藏夹——tags 先顶着。等到需要「牌组有自己的名字、描述、学习进度」时再建实体，现在建就是空壳。
