# System Prompt 与 LLM 返回契约

状态：JSON 字段与学习解释位置为待确认草案；自定义 Prompt 与 JSON 返回要求已确认。

## 用户设置

翻译、润色各自拥有 System Prompt，翻译并替换复用翻译 Prompt。首次显示完整默认内容，可编辑、保存，重启后保留。显示“默认”或“已自定义”，随时查看默认版本，恢复默认仅作用于对应操作。空白内容不能保存。默认文本见 [default-prompts.json](default-prompts.json)，单文件原型内嵌相同副本。

保存影响之后的新请求，不改变已发送的请求、现有结果或历史。编辑草稿在保存前不影响已生效设置。恢复默认先填回编辑器，点击保存后生效。

## 请求组成与固定格式

应用以用户选择的 Prompt 作为行为指导，并附加固定的响应契约、当前操作、目标语言及语境。原文放在独立的数据消息中，不拼接进 System Prompt。用户 Prompt 不得解除 JSON 结构、源文匹配、目标语言和安全写回约束。

只接受一个完整 JSON 对象。无 Markdown 围栏、前后说明或额外字段。解析模型消息内容中的 JSON，而不是把供应商的 HTTP 响应外壳当作本契约。

支持结构化输出的服务可使用响应 Schema 约束；其他兼容服务通过明确 Prompt 要求 JSON，但仍执行完全相同的本地校验。不得在校验失败后退回原始文本写回。具体供应商的格式参数在原生接入阶段依据其文档确定。

## 翻译与润色结果

按 [responses.schema.json](responses.schema.json) 中 `$defs.result` 校验：

```json
{
  "source_language": "en",
  "target_language": "zh-Hans",
  "segments": [
    {"source": "Good morning. ", "target": "早上好。"},
    {"source": "Let's begin.", "target": "我们开始吧。"}
  ]
}
```

- 语言使用 BCP 47 标签，如 en、ja、zh-Hans，不限定具体语言清单。
- 每个 segment 是同一语义句组的原文与结果，必要时允许一组多句，不假设两种语言具有相同的句号数量。
- 按顺序拼接全部 `source`，必须与本次提交的原文逐字符一致。包括原有空格与换行；分隔符附在对应片段中，不凭显示行数重新对齐。
- 拼接全部 `target` 得到复制、替换及历史的完整结果。模型应在片段内保留适当空格／换行，应用不额外插入空格。
- 翻译返回的目标语言须与请求一致；润色的目标语言须与原文语言一致。语言标签比较需按规范等价处理，不能据此保证模型的语义质量。
- 单段 `source`、`target` 均不能空白。润色无修改时允许两者相同。
- 主响应只包含结果与配对，不包含学习推荐。修改对照由配对原文和结果展示；学习开启时，再解释有学习价值的修改。

## 学习内容

学习请求使用对应翻译／润色 Prompt 的行为上下文，附加学习任务及 `$defs.learning` 契约。仅在开启学习或本次明确展开时发起，主结果先显示／写回；不等待学习完成。

```json
{
  "items": [
    {
      "text": "take a step back",
      "language": "en",
      "kind": "phrase",
      "meaning": "退一步重新审视；适合在讨论中建议换个角度。",
      "context": "Let's take a step back."
    }
  ]
}
```

`meaning` 使用中文。润色场景在此解释改善原因并区分语法错误与风格偏好。`context` 必须来自本次原文或结果，`text` 必须出现在该语境中。不强凑条目，允许 `items: []`。同一契约用于手动收藏后补充释义，不因学习关闭而禁止用户主动收藏。

## 失败处理

JSON 解析失败、字段缺失／类型不符、空结果、源文拼接不一致或目标语言不匹配时：显示“返回格式不符合要求”，保留原文、允许重试；不复制模型原始返回作为译文、不执行替换、不写成成功历史。不要用正则抽取第一个花括号片段后冒充有效响应。

学习 JSON 失败只影响学习区，可单独重试，已经得到的主结果仍可使用。用户自定义 Prompt 即使要求非 JSON，也不改变这些边界。
