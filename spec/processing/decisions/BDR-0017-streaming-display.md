# BDR-0017 · 模型返回的流式显示

状态：已接受（2026-10-17）。设计全文见 [streaming-output.md](../../../docs/streaming-output.md)，该文列出的四个待定决策在此裁定。

## 裁定

1. **替换入口采用方案 A（原子替换）。** 流式期间浮窗逐段显示到达的文字并保留处理态语义；替换与复制仍只认校验通过的结果。控件不做置灰状态，但流中按下替换或复制必须给出可见理由——不是静默无反应（设计稿 B 的折衷：A + 按压时的可见说明）。
2. **partial 不进历史。** 历史记的是成功结果；partial 未过本地校验，写入等于把未校验文本当成成功（contract.md「失败处理」）。
3. **接入翻译／润色与阅读查词。** 面板（浮窗）与主窗口（翻译／润色页面）都在到达时显示文字，且接收中的排版跟随显示方式：逐句对照逐对长出，原文／译文分段只长译文文字，定稿时不在两种排版之间跳变。学习推荐与按需补义保持整段返回：学习是后台请求，主结果先显示；补义单字段、收益最小。
4. **按后端能力自动降级。** `ModelBackend.stream` 给默认实现（整段当一个分片产出）；不能流式的后端零改动继续工作。增加 provider 不需要懂流式。HTTP 四家协议、Claude Code、Codex CLI 各自决定是否真流式；Codex 在本机实测整段到达，其流只是一个元素。

## 结论要点

- 流式只改「何时看见」，不改「何时可信」：请求契约、本地校验、写回门槛、纠正重试全部不变；`parse` 只吃完整文本，partial 永不进 `parse`。
- partial 在界面明确表达「正在接收，不是结果」：结果区只把已完整结束的 JSON 片段（翻译的 segment、查词的 meaning）取出来显示，原始 JSON 不直接示人；校验失败时 partial 丢弃、进错误态。
- 取消或切换请求后，已显示的 partial 清空，不残留到下一个请求。
- 调试页只记最终文本，不记整条流。
- 接收中的排版与定稿一致：面板与主窗口共用一处显示视图，按用户选择的显示方式排版，partial 永不提供查词原语（不接 `LookupOrigin`），也就不提供复制、替换或历史。
- 接收中的文字上方没有进度指示器（2026-10-18 修正，推翻原先「上方保留处理中标记」的写法）：转圈或「正在翻译…」与流动的文字并置，读起来像一条过期的标签，还白占一行；**文字本身即进度**。第一段文字到达前各界面维持自己的空态（面板为源文的占位形态，主窗口为居中的说明文字），第一段到达后让位给文字。
- 逐句对照下面板在收流期间就收起源文框（2026-10-18 修正）：面板高度上限 480，源文框压在上面会把正在生长的句组挤到可视区之外，用户只看到源文、以为译文要等整段返回才出现；句组自带原文，收起来与定稿一致。
- 到达的文字逐词显示，每个句组有最低停留时长（2026-10-18 新增，`RevealPace`）：整段跳出看不出「正在写」，而逐词的节奏本身就是过程。默认每词 20ms、每句组最长停留 100ms（有空余时才停留），并把已到达的文字全部显示完——不足两行的回答上限 0.5s，流特别快或一次返回很多句时节奏自动加快而不是一直拖。显示节奏只决定「何时看见」：状态、校验、复制、替换、历史一概不受影响。
- 一次待显示的文字超过两行时不再逐词（2026-10-18 新增）：`hurryWords`（30 词）以上的部分在 0.15s 内近似一次到位——一句话读着被写出来是过程，一段话谁也跟不上，逐词只是延迟。判断看两件事：**这次要显示的文字**超过两行（一次到达的整段直接铺开），或**整个回答**已经超过两行（长回答的后半段一到就铺开，不出现前几句慢慢写、后几句跳）。不足两行的回答不受影响，仍按每词 20ms 写出来。
- 定稿后显示继续补齐最后几个词（2026-10-18 新增）：校验通过时若仍有词在逐词显示中，结果按定稿接管要等显示追平——否则最后一句会从半句跳到整句，正是要避免的「闪」；期间的复制、替换、学习都按**完整结果**工作，界面不声称还在接收。显示追平后切换为定稿排版（带查词原语），不跳变文字本身。
- 整段到达的回答不做逐词（2026-10-18 新增）：回答只在一个分片内到达（服务不能流式、或一次性返回完）时按定稿一次性显示，与既有降级裁定「界面与今天完全一致」相同；逐词只用于真正分片到达的回答，「看起来像在写」不加给本来没有流的东西。
- 主窗口（翻译／润色页面）在 2026-10-17 的修正中一并接入：原「第一轮不改、loading 态保持现状」的裁定被推翻——接收中的文字必须与面板一样可见，并跟随显示方式。数据层此前已具备流式，本次只改显示。
