# BDR-0018 · 浮窗内的手动输入

状态：已接受，已实现（2026-10-23）。设计全文见 [manual-input.zh-CN.md](../../../docs/manual-input.zh-CN.md)，该文列出的四个待定决策在此裁定。

## 裁定

1. **读不到文字时，浮窗本身就是编辑器。** 读不到选区（含密码框、读取超时）时，浮窗展开为空的原文编辑器，光标就位，内容区保留「无法读取任何文字」作为说明，不带按钮；不发起请求，没有选区就不写回。工具栏已展开时同样清掉旧文字进入编辑。
2. **权限失败保留紧凑提示。** 它的出路是一键打开系统设置，编辑器帮不上忙。
3. **有文字时只加「编辑文本」。** 原文条上的铅笔展开浮窗并聚焦原文，光标在末尾；不加「新文本」清空动作（⌘A 加删除已能做到）。
4. **手动输入只在浮窗里。** 主窗口不再作为读取失败的出口，也不另设「在窗口中打开」。
5. **逐句对照下编辑时重新显示原文框。** 直到再次处理或浮窗关闭；再次处理成功后照常折叠为句对。
6. **⌘↩ 在没有可写回的选区时就是「处理」。** 有选区且已有结果时仍是替换；原文为空时不做事。
7. **迟到的读取不覆盖用户输入。** 读取超时后展开的编辑器里一旦有了文字，迟到的选区结果被丢弃。

## 原因

展开前遇阻不展示「等着设置或重试」的界面（BDR-0002）；但空的编辑器本身就是解决办法，展示它是最短路径。去掉一次窗口切换，读不到文字的场景从「提示 → 跳主窗口 → 输入」变成「直接输入」。

## 影响

- BDR-0002 增加例外：读不到文字不再是紧凑提示。
- `Notice.unreadable` 不再提供「输入文本」入口，面板不再需要打开主窗口的回调。
